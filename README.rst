sphinx-hackerrank
=================

Export Sphinx documentation as self-contained HTML for HackerRank Interviewer Guidelines, with styles and images.
Build and preview locally without HackerRank credentials.

Quick start
-----------

In an existing Sphinx project:

.. code-block:: console

   pip install sphinx-hackerrank

Add ``"sphinx_hackerrank"`` to ``extensions`` in ``docs/conf.py``.
Create ``docs/review.rst`` and add ``review`` to your existing toctree:

.. code-block:: rst

   Widget review
   =============

   .. hackerrank-export:: interviewer-guidelines/review.html
      :name: Widget review

      Interviewer instructions go here.

      .. code-block:: text

         example input

Build:

.. code-block:: console

   sphinx-build -W -b hackerrank docs build/hackerrank

Open ``build/hackerrank/interviewer-guidelines/index.html`` to preview the exports.
Upload ``build/hackerrank/interviewer-guidelines/review.html`` using your own publishing tool.

Code blocks are exported as ``<pre><code>`` with their original text and whitespace.
HackerRank's project IDE adds native copy controls to these blocks in its Guidelines tab.
Hover over a code block to reveal its Copy button.
Check copying inside a project interview.
The standalone preview displays the exported HTML without the IDE's controls.

Choosing content
----------------

Wrap content in ``hackerrank-export`` and give it an HTML output path relative to the build directory.
The required ``:name:`` option supplies the preview index label.
Each boundary is a Sphinx node carrying its destination and name.
No CSS selector or export list is needed.
Multiple boundaries in the same document export independently.
Destinations must be unique and must not overwrite documentation pages or the preview index.
The ``hackerrank`` builder writes only the standalone exports and their preview index.
Run the ordinary ``html`` builder separately for themed documentation pages.
When upgrading, clean an existing HackerRank output directory once to remove pages generated by earlier versions.

Python extensions can construct the same boundary directly:

.. code-block:: python

   """Declare an export around prepared Docutils content."""

   from docutils import nodes

   from sphinx_hackerrank import GuidelineExportNode

   content = GuidelineExportNode(
       output_path="interviewer-guidelines/review.html",
       name="Widget review",
   )
   content += nodes.paragraph("", "Interviewer instructions go here.")
   assert content.astext() == "Interviewer instructions go here."

The builder renders each marked subtree from Sphinx's resolved doctree using its standard HTML translator.
It preserves document context for headings, references, figure numbering, and images without rendering the rest of the page or loading a theme.
Export metadata is retained across incremental and parallel builds.
Other builders receive ordinary containers, preserving their native rendering without additional node handlers.

For collapsible sections, enable `sphinx-toolbox.collapse <https://sphinx-toolbox.readthedocs.io/en/stable/extensions/collapse.html>`_.
To reuse guide sections, enable `sphinx-section-include <https://github.com/adamtheturtle/sphinx-section-include>`_.
See the `sample project <https://github.com/adamtheturtle/sphinx-hackerrank/tree/main/sample>`_ for both.

Migrating from selector exports
-------------------------------

Replace each ``GuidelineExport`` configuration entry with a ``hackerrank-export`` directive or ``GuidelineExportNode`` around the content being exported.
Move ``output_path`` and ``name`` to that boundary, then remove ``hackerrank_exports`` and the old ``GuidelineExport`` import.
A separate ``docname`` and ``selector`` are no longer needed.
CSS classes remain presentation details.

Source links
------------

Relative document links retain their paths by default, so build a separate HTML site to supply the linked pages.
To link to hosted documentation, set ``hackerrank_source_url = "https://example.org/guides/"`` in ``conf.py``.
For source files, set ``hackerrank_source_suffix = ".rst"`` too.
Set ``hackerrank_source_anchors = False`` if the destination does not support anchors.
